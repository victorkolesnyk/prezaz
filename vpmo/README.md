# Віртуальний PMO

Портфельний офіс в одній особі плюс інструмент: тримає стан усіх проєктів портфеля в одному реєстрі, рахує сім цільових показників PRINCE2 7 проти допусків, перевіряє готовність до меж етапів, готує звіти про виняток і сценарії фінансування. Побудований для проєктів типу RENOVATOR, де КМС ЗСУ є бенефіціаром, а роботу виконують Виконавчі Агенти країн НАТО.

## Що всередині

`references/01-teoriia.md` — теоретична база: PRINCE2 7 (принципи, практики, процеси, сім показників, продукти), P3O, MoP, ISO 21504:2022, P3M3, з джерелами і рівнем достовірності.

`references/02-model-pmo.md` — операційна модель офісу: рівні портфеля, відповідність ролей PRINCE2 ролям проєкту Сайту, чому фази Trello не є етапами управління, допуски за замовчуванням, ритм роботи, маршрут ескалації.

`references/03-produkty.md` — управлінські продукти, їх відповідники в документах КМС і комплекти для кожної межі етапу.

`pmo/` — рушій на чистому Python 3 без залежностей.

`skills/` — чотири навички Claude: `portfel` (огляд портфеля), `shliuz-etapu` (межа етапу), `vykliuchennia` (звіт про виняток), `novyi-proiekt` (включення проєкту, пріоритизація фінансування).

`data/pryklad_portfel.json`, `data/pryklad_stsenarii.json` — вигадані дані для навчання і тестів. Реальний портфель лежить у `data/local/portfel.json`, ця тека в git не потрапляє.

## Команди

Запускати з теки `vpmo`.

```
python3 -m pmo check     data/local/portfel.json
python3 -m pmo dashboard data/local/portfel.json --trello site2.json site4.json --out out/portfel.md
python3 -m pmo gate      data/local/portfel.json RNV-S2 --trello site2.json
python3 -m pmo exception data/local/portfel.json RNV-S2 --trello site2.json
python3 -m pmo fund      data/pryklad_stsenarii.json
python3 -m pmo trello    site2.json site4.json
python3 -m unittest discover -s tests
```

Файли `--trello` є збереженими відповідями `trelloReadCard` з action `list_by_board`, тобто той самий формат, з яким працює плагін renovator-pm.

## Як рушій ухвалює висновки

Кожен із семи показників отримує один із чотирьох станів: у межах допуску, під загрозою (прогноз від 80 % допуску), виняток (прогноз за межею), немає даних. Кольорів немає навмисно: виняток визначає число.

Час: найбільше прострочення незакритої контрольної події в Trello, а також зсув кінця останньої фази проти дати закриття в портфелі. Це нижня оцінка: подія, що ще не настала, може зсунутися більше.

Вартість: прогноз при завершенні мінус базова лінія без резерву, проти допуску; якщо допуск не задано, допуском є резерв Листа-доручення.

Обсяг: вилучення позицій за пріоритетами MoSCoW. Якість: реєстр якості. Вигоди: недобір прогнозу проти плану у відсотках. Ризик: найвища оцінка ймовірність на вплив за шкалою 5x5 і наявність відповіді. Сталий розвиток: лише якщо метрику задано в бізнес-кейсі.

Відбір фінансування йде в порядку оцінки, обов'язкові позиції першими, кожна разом із попередниками. Суму оцінок на гривню рушій навмисно не максимізує: так дешеві другорядні позиції витіснили б дорогі важливі.

## Межі

Рушій не змінює Trello і нічого не надсилає. Оцінки за критеріями і допуски задають люди. Склад управлінських продуктів PRINCE2 7 узято з вторинних джерел, які частково розходяться; перед формальним використанням звірити з Додатком A офіційного посібника.
