# Запис звуку зустрічі Teams у файл

Скрипт `record_meeting.py` пише звукову доріжку онлайн-зустрічі (Teams, Zoom, Meet — будь-якої програми) в один файл. Записуються два джерела одночасно: системний звук (голоси інших учасників, що звучать у ваших навушниках чи динаміках) і ваш мікрофон. Типово вони лягають у різні канали стерео: ви ліворуч, інші праворуч.

Скрипт `transcribe.py` перетворює запис на текст на хмарній відеокарті Modal моделлю Whisper large-v3 і розмічає репліки «Я» та «Інші» за каналами. Див. розділ «Транскрипція».

Teams про запис не дізнається і нічого не показує учасникам. Попередити їх про запис і отримати згоду — ваш обов'язок. Якщо у вашої організації є ліцензія з вбудованим записом і транскрибуванням Teams, воно залишається офіційнішим шляхом: учасники бачать, що йде запис.

## Встановлення і запуск у Windows

Потрібен Python 3.9 або новіший (https://www.python.org/downloads/, під час встановлення позначте «Add python.exe to PATH»).

Найпростіше: двічі клацнути `record_meeting.bat`. Під час першого запуску він створить віртуальне середовище `.venv` поруч і встановить залежності (потрібен інтернет, завантаження займає кілька десятків мегабайтів). Далі запис починається одразу. Зупинка: `Ctrl+C` у вікні консолі, після чого файл закривається і вказується шлях до нього.

Запускачі `record_meeting.bat` і `record_and_transcribe.bat` пишуть лише звук із навушників чи динаміків, без мікрофона (`--no-mic`), у моно. Це розрахунок на наради, де ви слухаєте, а мікрофон у Teams вимкнено: скрипт бере мікрофон напряму з Windows, тож інакше в запис і в текст потрапило б усе, що ви говорите поруч, навіть коли в Teams мікрофон вимкнений. Щоб писати й свій голос (стерео з розміткою «Я» та «Інші»), запускайте з консолі без `--no-mic`: `.venv\Scripts\python record_meeting.py --transcribe`.

Вручну те саме:

```
cd tools\teams_recorder
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python record_meeting.py
```

Записи потрапляють у теку `recordings` поруч зі скриптом, назва файлу містить дату й час: `meeting_2026-09-23_14-00-05.mp3`.

## Параметри

```
python record_meeting.py --list                      # показати динаміки та мікрофони
python record_meeting.py --name "Нарада_з_ПР"        # префікс у назві файлу
python record_meeting.py --out D:\Записи             # інша тека
python record_meeting.py --duration 90               # автозупинка через 90 хвилин
python record_meeting.py --mono                      # звести обидва джерела в один канал
python record_meeting.py --transcribe                # після зупинки одразу транскрибувати
python record_meeting.py --bitrate 16                # ще менший файл
python record_meeting.py --format flac               # без втрат (mp3 | flac | wav)
python record_meeting.py --speaker "Jabra" --mic "Jabra"
python record_meeting.py --mic-gain 1.5              # якщо вас чути тихіше за інших
python record_meeting.py --no-mic                    # лише звук інших учасників (моно)
```

Типово файл пишеться в «диктофонному» MP3: 16 кГц, стерео, 24 кбіт/с на канал (48 кбіт/с разом), це приблизно 22 МБ на годину. З `--mono` удвічі менше, близько 11 МБ. 16 кГц достатньо для розпізнавання мовлення.

Бітрейт на канал змінюється параметром `--bitrate`; розмір за годину для стерео і моно:

```
--bitrate 16    близько 14 МБ (моно 7 МБ), найсильніше стиснення
--bitrate 24    близько 22 МБ (моно 11 МБ), типово
--bitrate 32    близько 29 МБ (моно 14 МБ)
--bitrate 40    близько 36 МБ (моно 18 МБ)
```

FLAC зберігає звук без втрат, але займає в кілька разів більше.

Стерео потрібне для розмітки «Я» та «Інші» при транскрипції. `--mono` має сенс, якщо файл іде в сторонній сервіс, який канали не розрізняє.

Для стерео-розмітки говоріть у навушниках. Якщо звук інших іде з динаміків ноутбука, мікрофон їх теж чує, і їхні репліки з'являться в тексті двічі: як «Інші» і як «Я».

MP3 пишеться потоком, тому навіть при аварійному закритті вікна вже записана частина залишається придатною до відтворення.

## Транскрипція

Розпізнавання працює на хмарній відеокарті NVIDIA L4 у сервісі Modal (https://modal.com): відеокарта вмикається лише на час обробки, оплата посекундна. Модель — Whisper large-v3 через faster-whisper. Наш код не пише ні аудіо, ні текст на диск і не виводить їх у журнали; у томі Modal лежить лише сама модель. Але сам Modal, за його документацією з безпеки, зберігає вхідні й вихідні дані функцій (тут це аудіофайл і готовий текст) у зашифрованому вигляді до 7 днів, після чого видаляє; дані понад 2 МіБ зберігаються в США. Modal Labs — американська компанія з Нью-Йорка. Чи допустима обробка ваших записів на такій інфраструктурі, вирішує ваша організація.

### Налаштування (один раз)

1. Зареєструйтеся на https://modal.com (безкоштовний тариф Starter містить щомісячний кредит на обчислення).
2. Двічі клацніть `setup_modal.bat`. Він встановить залежності, відкриє браузер для входу в Modal (`modal token new`) і розгорне функцію транскрипції (`modal deploy modal_app.py`). Перше розгортання збирає образ із CUDA, це займає кілька хвилин.

Вручну:

```
.venv\Scripts\modal token new
.venv\Scripts\modal deploy modal_app.py
```

Після змін у `modal_app.py` розгортання треба повторити.

### Користування

- `record_and_transcribe.bat`: запис, після `Ctrl+C` транскрипція одразу.
- `transcribe.bat`: перетягніть на нього один чи кілька вже записаних файлів.
- З консолі: `python transcribe.py recordings\meeting_....mp3 --srt`.

Поруч з аудіо з'являється `.txt` (з `--srt` ще й субтитри `.srt`):

```
[00:12:05] Я: Пропоную перенести на четвер.

[00:12:09] Інші: Згоден, але потрібне погодження.
```

Репліки однієї сторони з паузою до 3 с зливаються в один абзац. Хто саме з «Інших» говорить, програма не визначає. Моно-запис транскрибується без підписів. Свої підписи каналів: `--labels "Віктор,Партнери"`.

### Мови

Типово мова визначається окремо для кожного фрагмента мовлення між паузами серед двох основних мов, української та англійської. Рідкісні мови (литовська, шведська, латиська, норвезька, російська) призначаються фрагменту лише тоді, коли модель упевнена в них щонайменше на 60 % і вони ймовірніші за основні. Так англійське чи українське мовлення з акцентом не «переходить» у близьку рідкісну мову. Для російської поріг 85 %: Whisper часто дає українському мовленню помітну ймовірність російської, і нижчий поріг псував би саме український текст. Решта мов не розглядається зовсім. Якщо в нараді звучало кілька мов, біля реплік стоїть код мови:

```
[00:03:10] Я (uk): Колеги, переходимо на англійську.

[00:03:15] Інші (en): Thank you, let us start with the budget.
```

Інші набори: `--languages uk,en --extra-languages de,pl`. `--extra-languages ""` вимикає рідкісні мови. `--languages uk --extra-languages ""` вимикає визначення зовсім і трохи пришвидшує обробку.

### Наради з перекладачем

Мова визначається для кожного фрагмента між паузами, тому послідовний переклад (виступ англійською, переклад українською, і знову) розкладається правильно, якщо між оригіналом і перекладом є бодай коротка пауза. Фрагменти, коротші за 2 с, мову не визначають, а беруть її в сусіднього фрагмента, від якого їх відділяє менша пауза.

З `--split-languages` поруч із повним текстом з'являються окремі файли для кожної мови: `meeting.uk.txt` і `meeting.en.txt`. Український файл тоді містить ваші українські репліки разом з українським перекладом виступів, тобто повну українську версію наради, а англійський файл містить англійську версію.

Обмеження. Якщо перекладач починає говорити без паузи, поверх оригіналу (синхронний переклад в одному звуковому каналі), обидві мови злипаються в один фрагмент, і розпізнано буде лише одну з них. Окрема фраза рідкісною мовою коротше 2 с отримає мову сусідньої репліки. Whisper у такому разі зазвичай записує її приблизною транслітерацією або одразу перекладає.

Для латиської та литовської точність Whisper очікувано нижча, ніж для англійської й української: даних цими мовами в навчанні моделі значно менше.

Перший запуск після простою довший: відеокарта стартує і завантажує модель (при найпершому запуску модель, близько 3 ГБ, ще й завантажується в том Modal). Фактичні час і вартість видно в панелі Modal, розділ Usage.

## Якщо на записі тиша

Найчастіша причина: Teams виводить звук не на ті пристрої, що стоять типовими у Windows. Скрипт на старті друкує, які динаміки й мікрофон він пише. Порівняйте їх із налаштуваннями Teams (Налаштування, Пристрої, Аудіопристрої). Якщо відрізняються, вкажіть потрібні явно через `--speaker` і `--mic` (досить частини назви з `--list`).

Смужки рівнів у рядку стану показують, що сигнал надходить: `співрозмовники [#####.......]  ви [###.........]`. Якщо одна зі смужок постійно порожня, коли хтось говорить, ідеться саме про невірний пристрій.

Bluetooth-гарнітура в режимі гарнітури (Hands-Free) у Windows з'являється як окремий пристрій, відмінний від режиму «Стерео». Треба обрати той, що вибраний у Teams.

## Інші системи

Linux (PulseAudio, а також PipeWire через його сумісний з PulseAudio шар): запуск `python3 record_meeting.py`. Запис перевірено на PulseAudio з віртуальними пристроями.

macOS: системний звук напряму записати неможливо, бібліотека soundcard не підтримує loopback на macOS. Потрібен віртуальний аудіопристрій на кшталт BlackHole, налаштований як вихід Teams, і тоді його треба вказати як мікрофон. Цей сценарій не перевірено.

## Як це працює

Бібліотека `soundcard` відкриває loopback-потік динаміків (у Windows це WASAPI loopback) і потік мікрофона, обидва на частоті 16 кГц. Кожні 0,1 с скрипт читає блок з обох, розкладає по каналах стерео або зводить у моно і дописує у файл через `soundfile`. WASAPI loopback не віддає даних, поки в системі тиша, тому у Windows скрипт паралельно програє в ті самі динаміки нечутну тишу: так потік не переривається і доріжки не розсинхронізуються.
