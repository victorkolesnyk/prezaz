# Монітор згадувань «Реноватор»

Бот шукає в інтернеті згадування проєкту НАТО «Реноватор» (англ. Project/Operation Renovator: відновлення військових реабілітаційних центрів ЗСУ в межах Комплексного пакета допомоги НАТО) і веде реєстр: кожна знахідка отримує ідентифікатор, дату, джерело, мову, оцінку релевантності та статус. Реєстр зберігається у файлі `data/renovator/registry.jsonl`, поруч автоматично оновлюються `registry.csv` для Excel і `index.html` для перегляду в браузері.

Потрібен лише Python 3.11 або новіший. Сторонні бібліотеки не потрібні; пакет `anthropic` знадобиться тільки для необов'язкової класифікації моделлю Claude.

## Як він працює

Один прогін виконує шість кроків. Спершу конектори опитують джерела. Потім знахідки зливаються в реєстр з дедуплікацією: та сама стаття, знайдена через GDELT і через Google News, стає одним записом, і в ньому лишається пряме посилання на видання. Далі кожен запис отримує оцінку від 0 до 100. Невизначені записи бот перевіряє, завантажуючи саму сторінку й шукаючи термін у тексті статті. За бажанням невизначені записи класифікує модель Claude. Наприкінці бот надсилає сповіщення в Telegram, зберігає реєстр і перегенеровує вивантаження.

| Джерело | Що дає | Ключ API |
|---|---|---|
| Google News RSS | новини українською, англійською, латиською, литовською, норвезькою, шведською | не потрібен |
| Bing News RSS | друга пошукова система для перехресного покриття | не потрібен |
| GDELT DOC 2.0 | світовий індекс онлайн-ЗМІ, глибина до 3 місяців | не потрібен |
| Пошукові стрічки WordPress | повнотекстовий пошук на конкретних виданнях (АрміяInform, UK Defence Journal та ін.) | не потрібен |
| GOV.UK Search API | офіційні публікації уряду Великої Британії | не потрібен |
| Telegram (t.me/s) | пошук у публічних каналах зі списку | не потрібен |

## Чому оцінка релевантності влаштована саме так

Англійське renovator є звичайним словом: так називають майстрів ремонту, мультитули, телешоу. Українське «Реноватор» натомість майже завжди означає проєкт. Тому кириличний термін і фрази на кшталт «Project Renovator» дають 50 балів, голе renovator дає 20. Якщо пошуковий рушій знайшов статтю за запитом із сильним терміном, а в заголовку терміна немає, це теж свідчення (30 балів): рушій шукав у повному тексті. Сім контекстних груп (НАТО, Україна, реабілітація, медицина, військові, країни-лідери, управління проєктом) додають по 10 балів, разом не більше 40. Маркери побутового ремонту, інструментів і розваг знімають по 15 балів.

Пороги: від 60 «релевантна», від 30 до 59 «потребує перевірки», нижче 30 «нерелевантна». Без жодного свідчення терміна запис не може стати релевантним, хоч би який сильний був контекст. У записі видно, що саме спрацювало (поля `term`, `context`, `negative`), тож будь-яку оцінку можна пояснити.

Рішення людини переважує модель, модель переважує правила. Нерелевантні записи не видаляються: вони лишаються в реєстрі, щоб наступний прогін не показав їх як нові.

## Швидкий старт

```bash
# Перше наповнення: максимальна глибина, без сповіщень про історичні статті
python -m renovator_monitor run --backfill --silent

# Звичайний прогін (так його запускає розклад)
python -m renovator_monitor run

# Що чекає на рішення людини
python -m renovator_monitor list --status uncertain --urls

# Ручне рішення: ID можна скорочувати до унікального початку
python -m renovator_monitor review 3f2a9c relevant --note "згадка в абзаці про Литву"
python -m renovator_monitor review 3f2a9c auto      # зняти ручне рішення

# Дайджест за тиждень у Markdown, статистика
python -m renovator_monitor digest --days 7 --output digest.md
python -m renovator_monitor stats

# Перевірити кожне джерело окремо, нічого не записуючи
python -m renovator_monitor doctor

# Після зміни правил у relevance.py переоцінити весь реєстр
python -m renovator_monitor rescore
```

Свої запити, сайти й канали задайте окремим TOML-файлом, який накладається на типовий `renovator_monitor/config.toml`: `python -m renovator_monitor --config my.toml run`. Таблиці зливаються, списки замінюються цілком.

## Розгортання

**GitHub Actions** (`.github/workflows/renovator-monitor.yml`) запускає прогін кожні 6 годин і комітить оновлений реєстр, тож історія git стає журналом аудиту. Перше наповнення: вкладка Actions, workflow `renovator-monitor`, Run workflow з позначкою backfill. Секрети репозиторію `RENOVATOR_TG_TOKEN` і `RENOVATOR_TG_CHAT_ID` вмикають сповіщення; змінна репозиторію `RENOVATOR_LLM_ENABLED=1` разом із секретом `ANTHROPIC_API_KEY` вмикає класифікацію моделлю. Розклад спрацьовує лише з гілки за замовчуванням.

**Docker**: `docker-compose up -d renovator-monitor` запускає цикл `watch` з інтервалом у годину; змінні беруться з `.env`.

**cron на сервері**: `17 */6 * * * cd /шлях/до/репозиторію && python3 -m renovator_monitor run >> data/renovator/run.log 2>&1`.

Код виходу `run`: 0 у разі успіху (навіть часткового), 2, якщо жодне джерело не відповіло, 1 у разі помилки конфігурації чи реєстру.

## Поля реєстру

`id`, `url` (пряме посилання на видання, коли воно відоме), `alt_urls`, `title`, `snippet`, `source_name`, `domain`, `language`, `published_at`, `first_seen_at`, `last_seen_at`, `found_via` (джерело і запит), `score`, `auto_status`, `term`, `context`, `negative`, `page_term` і `page_excerpt` (результат перевірки сторінки), `llm` (вердикт, тональність, суть одним реченням), `manual_status`, `notes`, `notified`. Усі дати в UTC.

## Обмеження, про які треба знати

Google News віддає посилання-перенаправлення на news.google.com, тому сторінки таких знахідок бот не перевіряє; якщо ту саму статтю знайде GDELT, Bing або WordPress-пошук, запис отримає пряме посилання. Глобального пошуку по Telegram без облікового запису немає: бот перевіряє лише канали, внесені в `[sources.telegram] channels`, і цей список навмисно порожній, доки ви не впишете перевірені назви. Соцмережі із закритим API (Facebook, Instagram, X, LinkedIn) не охоплені. GDELT обробляє неанглійські матеріали через машинний переклад, тому запити до нього англійською; україномовне покриття дають Google News, Bing і WordPress-пошук. Формати зовнішніх джерел можуть змінюватися без попередження: команда `doctor` показує, яке джерело перестало відповідати.
